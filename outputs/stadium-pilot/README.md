# Центральный стадион Алматы — визуальный прототип

Прототип показывает общий вид стадиона, позволяет выбрать условную трибуну, сектор, ряд и кресло, посмотреть поле из выбранной позиции и пройти демонстрационное оформление. На трибуне можно нажать на кресло и сразу перейти к виду с него.

Общая 3D-модель и расположение кресел приблизительные, а нумерация условная. Номера секторов и направление их нумерации взяты по [схеме оператора](https://centralstadium.kz/shema-stadiona/?lang=ru) (картинка без даты; запад с юга на север, север с запада на восток, восток с севера на юг, юг с востока на запад); их границы, ряды и места распределены в модели ориентировочно. Отсутствие 29, 38 и 39 не доказывает отсутствия этих секторов на стадионе. Вид из выбранного кресла строится в упрощённой 3D-модели. Фотореалистичная модель и проверенные виды с мест ещё не готовы. Билет не выпускается и оплата не проводится.

## Запуск

```bash
npm install
npm run dev
```

Откройте адрес, который выведет команда. Перетаскивайте сцену, чтобы вращать общий вид или осмотреться с выбранного места.


## Детали реализма в основной сцене

Все размеры ниже ориентировочные: стандартные для футбольного поля или подобранные по фотографиям, но не измеренные на стадионе.

- Ворота с сеткой, угловые флажки (колышутся на ветру), рекламные борта вокруг поля, скамейки запасных на западной стороне, точки пенальти и дуги штрафной.
- Предметы у поля (`src/pitchSide.js`): щиты с собственными макетами без настоящих брендов, скамейки с изогнутыми навесами, решётки стока, люки, барьеры, камеры, урны, а за воротами маты и яма для прыжков. Их состав и расположение предположительные.
- Номера и финишная линия на беговых дорожках.
- Газон и разметка футбольного поля (`src/pitchGrass.js`): полосы покоса, меняющие яркость от угла взгляда, неоднородность травы, потёртости у ворот и сглаженные линии считаются в шейдере. Плоские линии и пятна остаются для экспорта в Blender и сравнения (`?grass=old`).
- Барьер с синей светодиодной лентой перед первым рядом; поручни проходов — металлические трубки со стойками.
- Бетон с разводами (шум по мировым координатам).
- Дальние трибуны (`src/standShading.js`): тон кресел зависит от места, ряда и крупных пятен, есть выгоревшие кресла; издали низ спинки темнее, а кромка светлее, поэтому ряды читаются; лёгкая дымка. Считается в шейдере без новых текстур. Сравнить с прежним: `?stands=old`.
- Деревья на зелёных участках вокруг стадиона (одним `InstancedMesh`, расстановка воспроизводимая).
- Табло с текстом, светящиеся лампы мачт, переключатель «День / Вечер».
- Тени 4096 px, отражения неба из `sky.hdr`.

Модели собираются в Blender скриптами из `work/blender/` (`make_tribuna.py` — детальный фрагмент трибуны для `tribuna-test.html`). Запуск без окна: `Blender -b -P make_tribuna.py`.

## Производительность

Цель: стабильные ~60 кадров/с на ноутбуке и телефоне при сохранении вида. Что для этого сделано:

- **Две детализации кресел.** В общем виде кресло из 36 треугольников; детальная модель (около 200) показывается только для мест выбранного сектора и для окрестности (24 м) кресла в виде с места. Было ~5,4 млн треугольников на кадр, стало ~1,0 млн в общем виде и ~0,2 млн в секторе.
- **Объединение статичных объектов.** Мелкие объекты с одним материалом (поручни, разметка, борта, таблички) склеиваются в один меш; таблички секторов рисуются одним атласом. Вызовов отрисовки было ~300, стало ~74.
- **Рендер по требованию.** Неподвижная сцена не перерисовывается, а при движении частота ограничена ~60 кадрами/с (на 120 Гц экранах тоже).
- **Адаптивное разрешение.** Если кадр дольше ~19 мс, внутреннее разрешение снижается (до 0,65), периодически пробует вернуться. На телефонах старт с 1,25.
- **Затенение в контактах (GTAO)** только на компьютерах и только в близких видах (сектор, место); отключается само при <22 кадров/с. `?fx=0` выключает вручную.
- **Телефоны:** тени 2048 вместо 4096, облегчённый шейдер потёртостей бетона, без GTAO и подсказок при наведении.
- Отладка: `?debug=1` делает доступным `window.__debug` (renderer, scene, camera) для `renderer.info`.
- **Размер загрузки.** Текстуры газона и бетона переведены в WebP (−0,4 МБ), неиспользуемые панорамы и старая модель трибуны удалены из `public/` (−1,7 МБ в сборке). Модули затенения (GTAO, EffectComposer) подгружаются отдельным файлом и только на компьютерах. На первый показ сцены уходит около 3 МБ (из них небо 1,1 МБ, рельеф 0,9 МБ, скрипт 0,2 МБ в сжатом виде).
- **Уровни качества.** Компьютер: тени 4096, затенение в контактах (GTAO) в близких видах, вечерний режим со свечением ламп и лент (bloom), радиус детальных кресел 48 м, разрешение до 1,5. Телефон: тени 2048, облегчённые шейдеры бетона, без GTAO и bloom, радиус детальных кресел 28 м, разрешение 1,25 с автоподстройкой. Тяжёлые эффекты отключаются сами, если не хватает кадров.

## Предрендеренные панорамы для вида с места (пилот)

Идея из исследования: вид с места можно не считать вживую, а показывать готовый рендер из Blender Cycles (трассировка лучей, запечённый свет и тени). На телефоне это одна текстура на сфере вместо тяжёлой сцены.

- `?debug=1` + `window.__debug.exportScene()` в консоли браузера сохраняет текущую сцену в `work/exports/stadium-scene.glb` (работает только на dev-сервере).
- `work/blender/render_panorama.py` рендерит панораму из этой сцены в заданной точке (координаты Three.js): `Blender -b -P render_panorama.py -- --glb ../exports/stadium-scene.glb --pos X Y Z --out out.jpg --lon 75 --lat-up 40 --lat-down 40 --ppd 22 --samples 24`. Рендерится только нужный сектор обзора (±75° по горизонтали), а не вся сфера.
- `public/panoramas/index.json` — список узлов (позиция, файл, углы); для ближайшего к креслу узла (радиус 3 м) вид с места показывается панорамой, иначе живой сценой.
- Замер пилота (одно место, сектор 5, ряд 7, место 12): рендер 44 с, файл 640 КБ, 3300×1760 px.
- Сейчас узел один. Для всей чаши нужна сетка узлов (по секторам и блокам рядов) и пакетный рендер.

Бетон трибун: Poly Haven, Damaged Concrete Floor, CC0 — https://polyhaven.com/a/damaged_concrete_floor (цвет осветлен и приглушён, нормали и шероховатость на компьютерах). Исходные JPG 1k лежат в `work/textures/damaged_concrete_floor`. Старая текстура `rough-concrete.webp` остаётся для тестовой страницы.

## Удобство

- **Ссылка на место:** в адресе `#трибуна/сектор/ряд/место` (например `#east/30/3/3`) открывает вид с этого места сразу; адрес обновляется при выборе.
- **Esc** возвращает на шаг назад: из вида с места к сектору, из сектора ко всем секторам, затем закрывает панель.
- **Предзагрузка панорам:** при выборе сектора панорамы его узлов подгружаются заранее (кэш из 4 на компьютере и 2 на телефоне), поэтому «Да, посмотреть с места» открывает картинку без паузы.
- **Индикатор загрузки** модели с процентами.
- **Проверка пакета панорам:** `python3 work/blender/verify_panoramas.py` (все ли узлы на месте, размеры, покрытие секторов, отчёт в `work/panoramas-report.md`) и `work/blender/make_contact_sheet.sh` (контактный лист всех панорам в `work/panoramas-contact-sheet.jpg`).
- **Быстрее первый показ:** горы подгружаются через 1,5 с после первого кадра. **Кэш панорам:** в собранной версии `sw.js` (service worker) хранит уже скачанные панорамы на устройстве, повторные заходы и возврат к виденным местам не качают файлы заново.
- **Версия набора панорам** (`PANO_VERSION` в `src/main.js`): после перерендера панорам увеличьте число, тогда кэш на устройствах обновится. Ресурсы берутся относительно базового адреса (`base: './'`), приложение работает и в подпапке хостинга.
- **Вид с места по умолчанию строится живой 3D-сценой из самого выбранного кресла.** Предрендеренные панорамы (вид из ближайшей точки сектора) отключены: они давали похожий ракурс, но не точное место. Код и файлы сохранены, включить можно параметром `?pano=1` в адресе.
- **Запечённое затенение из Blender (вид сверху).** `work/blender/bake_ao_topdown.py` считает в Cycles, сколько света неба доходит до каждой точки сцены (под креслами, в углах ступеней, под крышей темнее), и сохраняет карту `public/ao-top.webp` (4096 px, на телефонах `ao-top-2k.webp`). Карта накладывается по мировым координатам (x, z) на бетон, дорожки, газон и землю; нагрузки на видеокарту практически нет. Пересчёт: `Blender -b -P bake_ao_topdown.py -- --glb ../exports/stadium-scene.glb --out ../exports/ao-top.png` (около 3 минут), затем WebP. Сила эффекта: `uAoStrength` в `src/main.js`.

## Вступительный облёт

На общем виде запускается короткий бесшумный ролик из Blender Cycles. При первом нажатии или использовании клавиатуры он уступает место интерактивной модели. При открытии ссылки на место, включённом сокращении движения или экономии трафика ролик не запускается. Для телефонов используется видео меньшего размера. Ролик показывает приблизительную модель стадиона.

Чтобы пересчитать кадры, сначала экспортируйте актуальную сцену через `window.__debug.exportScene()` на локальном сервере, затем выполните из корня проекта:

```bash
nice -n 15 /Applications/Blender.app/Contents/MacOS/Blender -b -P work/blender/render_orbit.py -- --samples 16 --width 1280
```

Кадры сохраняются в `work/exports/orbit-frames/`. Экспорт сцены не переносит вычисляемое в браузере затенение; освещение и материалы ролика настроены отдельно в Blender.

Готовые кадры кодируются FFmpeg в `public/stadium-orbit-desktop.mp4` и `public/stadium-orbit-desktop.webm` (1280×720), а также в `public/stadium-orbit-mobile.mp4` и `public/stadium-orbit-mobile.webm` (640×360). Все версии содержат 144 кадра с частотой 24 кадра/с; звук отсутствует.

```bash
ffmpeg -framerate 24 -start_number 1 -i work/exports/orbit-frames/frame-%04d.png -an -c:v libx264 -preset fast -crf 26 -pix_fmt yuv420p -movflags +faststart outputs/stadium-pilot/public/stadium-orbit-desktop.mp4
ffmpeg -i outputs/stadium-pilot/public/stadium-orbit-desktop.mp4 -vf scale=640:360 -an -c:v libx264 -preset fast -crf 27 -pix_fmt yuv420p -movflags +faststart outputs/stadium-pilot/public/stadium-orbit-mobile.mp4
ffmpeg -i outputs/stadium-pilot/public/stadium-orbit-desktop.mp4 -an -c:v libvpx-vp9 -b:v 0 -crf 35 -deadline good -cpu-used 5 -row-mt 1 outputs/stadium-pilot/public/stadium-orbit-desktop.webm
ffmpeg -i outputs/stadium-pilot/public/stadium-orbit-mobile.mp4 -an -c:v libvpx-vp9 -b:v 0 -crf 35 -deadline good -cpu-used 5 -row-mt 1 outputs/stadium-pilot/public/stadium-orbit-mobile.webm
```

**Главный фасад (западный вход).** Собственная модель (`work/blender/create_west_facade.py`, `public/west-facade.glb`, около 2,6 тыс. треугольников): арка на пять опор, балка с балюстрадой и вывесочной панелью, две башни с медальонами, ворота, низкие крылья. Фасад сдвинут от центра на 103 м, чтобы не пересекаться с опорами крыши; соединение с трибуной остаётся приблизительным. Пропорции оценены по фотографии главного фасада (Wikimedia Commons, «Ortalyq-Almaty_2022e», автор CD, CC BY-SA 4.0: https://commons.wikimedia.org/wiki/File:Ortalyq-Almaty_2022e.jpg) только как ориентир; геометрия своя, без логотипов, скульптур и надписей. ### Подготовленные модели и новые габариты

Собственная крыша `public/stadium-roof.glb` создана скриптом `work/blender/create_stadium_roof.py`: настил примерно 149 × 39 м с продольными швами, высота около 20 м, западная сторона. Для приближённых габаритов чаши 227 × 175 м подготовлен отдельный Blender-предпросмотр `work/blender/create_scaled_bowl.py` на основе локального экспорта мест; в полученный `.blend` также входят упрощённые поле с воротами и разметкой и дорожка, крыша, восточные мачты и сдвинутый фасад; цвета кресел условные; добавлены рельеф Алатау и HDR-небо из проекта, но здания и деревья не включены; перед трибунами добавлен барьер. В файл добавлены камера и освещение для самостоятельного рендера. Скрипт отдельно экспортирует статичную геометрию чаши без кресел в `work/exports/stadium-bowl-static.glb`; бетонные поверхности имеют UV-координаты; текстуры бетона Poly Haven (CC0) упакованы в `.blend`, а GLB использует материал без встроенных текстур. Это подготовительный файл, к сайту не подключён. На сайте остаётся прежняя чаша до интеграции. Данные размеров — ориентиры из предоставленного исследования OpenStreetMap, фактические места и ряды не обмерены. Порядок интеграции и параметры карты затенения описаны в `work/stadium-geometry-handoff.md`. Новые модели созданы для проекта, сторонние модели не использованы.

HDR-небо на компьютерах: `sky-2k.hdr`, Poly Haven, Kloppenheim 05 Pure Sky 2k, CC0 — https://polyhaven.com/a/kloppenheim_05_puresky. На телефонах остаётся лёгкий `sky.hdr` 1k. Режим максимального качества (разрешение экрана 2×, постоянное затенение, глянцевые кресла) включается только адресом `?quality=max`; по умолчанию плавный режим с адаптивным разрешением.

Фактура газона (нормали, компьютеры): ambientCG, Grass004, CC0 — https://ambientcg.com/view?id=Grass004. Исходники 1k лежат в `work/textures/grass004`.

Вечерний свет: карта освещённости от четырёх прожекторов запечена в Blender Cycles (`work/blender/bake_floodlight_topdown.py`, вид сверху, те же границы, что у карты затенения) в `public/light-evening.webp`. Вечером она накладывается на бетон, дорожки, газон и землю по мировым координатам. Перезапекать вместе с картой затенения при изменении чаши, крыши или мачт: `Blender -b -P bake_floodlight_topdown.py -- --glb ../exports/stadium-scene.glb --out ../exports/light-top.png --px 2048 --samples 96 --power 1.2e6` (при необходимости `--bounds` и `--masts`).

Скрипт вечернего света принимает полную сцену в формате GLB или Blender (`--glb` или `--blend`). Для будущей сцены с четырьмя восточными мачтами параметры пробного запекания вечернего света приведены в `work/stadium-geometry-handoff.md`. Текущая карта рассчитана для старых угловых мачт; менять её следует после обновления и повторного экспорта полной сцены.

Увеличенная чаша: трибуны растянуты до 227 × 175 м (по данным OpenStreetMap) коэффициентами `bowlScaleX/bowlScaleZ` в `src/main.js`; поле, дорожки, кресла и высоты прежние, число мест и секторов не изменилось. Четыре мачты по 40 м стоят на восточном краю (`floodlight-masts.glb`), крыша только над западной трибуной (`stadium-roof.glb`). Карты затенения и вечернего света перезапечены для области x ∈ [-125, 125], z ∈ [-105, 105] (`--bounds -125 125 -105 105`; мачты `--masts "-84,94;-28,94;28,94;84,94" --mast-height 38.5`). Размеры, число рядов и положение мачт приблизительные.

Поведение выбора места (подсветка сектора с приглушением остальных, сброс через 260 мс, два касания на телефоне, подсветка ряда, кубическая ease in-out для облётов) воспроизведено по наблюдениям за демо Halden Arena (Ascenta Studio): перенесены только приёмы интерфейса, описанные в `work/halden-behavior.md`; модели, изображения, видео и тексты демо не использованы. Вид с места остаётся живой камерой в координатах выбранного кресла.

Проверка плавности: добавьте `?fps=1` к адресу, и в левом нижнем углу появится счётчик (частота, среднее время кадра и 95-й процентиль, разрешение, вызовы отрисовки, число треугольников, текущий вид).

Автоподбор качества: при запуске короткий замер видеокарты (полноэкранный шейдер 512×512) выбирает уровень `low` / `mid` / `high` / `max`; телефоны не выше `mid`. Пороги (на ноутбуке с Apple Silicon замер около 0,5 мс): до 2,5 мс — high, до 14 мс — mid, иначе low. Уровень влияет на разрешение (1,25 / 1,75 / 2 / 2), карты теней (2048 / 3072 / 4096 / 8192), число и радиус подробных кресел, нормали бетона и газона, размер неба и карты затенения. Во время работы разрешение дополнительно подстраивается под реальную частоту кадров. Принудительно: `?tier=low|mid|high|max`; счётчик `?fps=1` показывает выбранный уровень.

Чёткий кадр в покое: когда камера замерла на 0,2 с, сцена дорисовывается несколько раз с долей пикселя сдвига и кадры усредняются в линейном HDR (проходов 4 / 8 / 12 / 24 на уровнях low / mid / high / max), затем тонмаппинг; после последнего прохода отрисовка прекращается (экономия батареи), при любом движении возвращается обычный быстрый кадр. В вечернем режиме с композитором и при `?quality=max` не используется. `?refine=0` отключает, `?refine=N` задаёт число проходов.

## Готовый план секторов

`public/pre/plan/` содержит WebP-планы desktop 2560×1440 и phone 1170×1700, PNG-маски `plan-*-id.png` и `sectors.json`. Маска хранит фактический номер сектора как `R + 256 * G`, 0 — фон; фильтрация маски должна сохранять целые значения пикселей. В JSON для каждого сектора указаны трибуна, название, число мест и для каждого размера `center` и `bounds` в пикселях от левого верхнего угла; правый и нижний края границ исключены. Секторов 57: номера 1–60 без 29, 38 и 39. Скрипты `work/blender/render_sector_plan.py` и `work/blender/create_sector_masks.py` используют одну камеру. Подключение к интерфейсу ещё требуется.

В каждом наборе координат `desktop`/`phone` поле `polygons` содержит контуры по границам пикселей маски, координаты также отсчитываются от левого верхнего угла; внешний и возможные внутренние контуры передаются отдельными массивами.

Облёт: `pre/orbit/manifest.json` содержит размеры и SHA-256 отрендерированных файлов. Новые видео намеренно не отправлены в git из-за размера: desktop-файлы уже отслеживаются в репозитории и локально заменены, phone-файлы игнорируются; при чистом checkout нужно передать или заново собрать соответствующие файлы. Постеры `intro-desktop.jpg` и `intro-phone.jpg` входят в репозиторий. Скрипт рендера: `work/blender/render_orbit.py`; к новому phone-файлу интерфейс ещё не подключён.

Экспериментальные карты света для west/9 и east/46 лежат в `pre/light/pilot/` с описанием `manifest.json`. Они не подключены и не являются готовым освещением стадиона. Непрозрачные пиксели соответствуют `(pathIndex, rowIndex)`; за пределами пилота A=0 и требуется нейтральное значение. Подробные проверки и ограничения — в `work/prerender-plan.md`.
