## Цель проекта
Максимальная реалистичность вида «как в Reels» (3D-билетная арена: реалистичные кресла, мягкий свет, запечённые тени) при стабильных 60 FPS на телефоне и ещё лучшем качестве на компьютере. Пользователь выбирает трибуну, сектор, место и видит поле именно ИЗ ЭТОГО кресла.

## Что уже есть (не ломай)
- Поток выбора: общий вид → трибуна → сектор (остальные скрыты) → клик по месту (подсветка) → «Да, посмотреть с места» → вид из кресла. Ссылки `#east/30/3/3`, Esc назад, стрелки переключают соседние места, подсказка «Ряд · место» при наведении.
- Сцена (`src/main.js`, около 1900 строк): чаша на 24 305 кресел через `InstancedMesh`; две детализации кресла (простое 36 треугольников, детальное из `public/stadium-seat.glb` вблизи); объединение статичных мешей; рендер по требованию с ограничением ~60 кадров/с; адаптивное разрешение; затенение GTAO и bloom только на компьютерах; на телефонах (`pointer: coarse`) облегчённые шейдеры и тени 2048.
- Запечённое затенение из Blender: `work/blender/bake_ao_topdown.py` → `public/ao-top.webp` (4096) и `ao-top-2k.webp` (телефон), накладывается шейдером по мировым (x, z) на бетон, дорожки, газон, землю и кресла.
- Окружение: рельеф гор (GLB), здания и зелень из данных OpenStreetMap, деревья, табло, мачты, борта, ворота, скамейки запасных, переключатель День/Вечер.
- Интерфейс: зелёно-золотая палитра, скруглённые карточки, шаги выбора. Пользователь ненавидит «ИИ-слоп» (декоративные шрифты, стрелки-иконки, градиенты): держи интерфейс спокойным и функциональным.
- Предрендеренные панорамы (Cycles, 228 узлов, 115 МБ в `public/panoramas/`, в git не лежат) ОТКЛЮЧЕНЫ по умолчанию: пользователю не понравился «ракурс из ближайшей точки сектора, а не из его кресла». Включаются `?pano=1`. Проекция панорамы на упрощённую геометрию растягивала кресла: пробовали и откатили. Не возвращай панорамы по умолчанию без явной просьбы.

## Как работать
```bash
cd outputs/stadium-pilot
npm install
npm run dev -- --host 127.0.0.1 --port 5199   # dev-сервер
npm run build                                   # проверка сборки
```
- `?debug=1` даёт `window.__debug` (renderer, scene, camera, `exportScene()`, `exportSeats()`); `exportScene()` сохраняет GLB сцены в `work/exports/` (только на dev-сервере).
- Blender 5.3: `/Applications/Blender.app/Contents/MacOS/Blender -b -P скрипт.py -- аргументы`. Скрипты в `work/blender/`: кресло, крыша, рельеф, `bake_ao_topdown.py`, `render_panorama.py`, `render_batch.py`, `plan_nodes.py`, `verify_panoramas.py`.
- Рендер долгий и грузит видеокарту: запускай в фоне с `nice`, не гоняй параллельно тесты в браузере.
- Коммить маленькими логичными коммитами и пушь в `main`. Не добавляй `node_modules`, `dist`, `*.webp` панорам.

## Ловушки, на которые уже наступили
- Цикл рендера «по требованию» не рисует кадры, пока вкладка/панель скрыта; в браузерной панели перед скриншотом «разбуди» страницу (`window.dispatchEvent(new Event('pointermove'))`) и подожди 2–3 секунды.
- Ссылка с `#` в уже открытой вкладке не перезагружает страницу: есть обработчик `hashchange`.
- Абсолютные пути ресурсов запрещены: используй `asset('имя')` (базовый адрес сборки `./`).
- Не качай неизвестные npm-пакеты и файлы без согласия пользователя; бесплатные CC0-текстуры (Poly Haven) используй осознанно и описывай источник в README.
- Проверяй не только удачное место: смотри крайние кресла сектора, портретный экран телефона (375×812) и вечерний режим.

## Что делать дальше (по приоритету)
1. **Видео-облёт стадиона из Blender** для главного экрана в стиле рилса: орбита камеры 6–8 секунд, 1280×720 или 1920×1080, Cycles с шумоподавлением, сцена из `work/exports/stadium-scene.glb` (пересоздай через `exportScene()`), кодирование H.264 и WebM до нескольких МБ, автозапуск без звука, цикл; на экране выбора живая сцена остаётся для кликов, видео служит вступлением/фоном, на телефонах лёгкая версия.
2. **Детальные поручни, ограждения, барьер и выходы** в Blender (стойки, поперечины, стекло, кромки ступеней, подступенки), с запечёнными нормалями и без роста числа вызовов отрисовки.
3. **Запечённый вечерний свет** отдельным набором (прожекторы, тени от мачт, тёмное небо) вместо простого затемнения.
4. **Улучшение модели кресла** (текстура пластика, швы, потёртость, нормали) с сохранением бюджета треугольников (≤ ~600 вблизи).
5. **Замеры на реальном телефоне** (FPS, температура, память) и дальнейшая оптимизация; цель 60 FPS.
6. **Публикация:** статический хостинг, относительные пути, сервис-воркер кэширует панорамы (если вернуть `?pano=1`).
